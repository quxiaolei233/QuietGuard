# QuietGuard · 轻量闲时关机

全新 C17 / Win32 原生实现，Windows 11 x64。故障定位版本 0.3.1。

**当前状态：0.3 安全入口已在真实 Windows 上完成测试，磁盘采集间歇失效仍待定位。0.3.1 为这次故障增加准确的分项错误与 raw 计数器证据，并修正“一个格式化错误必定连带丢掉下一次有效采样”的恢复问题；它尚未在 Windows 上复测，不能宣称已解决真实环境中的磁盘异常。**

此前 0.3 的有限 Windows 测试观察到间歇性磁盘采样无效，不能据此宣称完整传感器验收。0.3.1 增加故障证据并改进恢复逻辑，但尚待 Windows 复测。技术说明见 `docs/DISK-DIAGNOSTIC.md`；旧暂停态测量不代表运行负载。

## 界面与设置

“总览”显示状态与四项指标；“监测规则”调整阈值、持续时间和采样；“启动与保护”选择登录/开机服务并设置会话保护。底部操作栏固定可见。切换页面不会保存或应用草稿；小屏只滚动内容区，没有横向滚动条。

新界面使用原生控件、圆角卡片和中文UI字体；绘图缓冲仅在界面显示时按需分配，隐藏或最小化时释放。还需要在真实 Windows 上复核显示效果与拖动闪烁。

## 它做什么

选中 CPU、GPU、磁盘、网络中的任意组合。只有每项读数都有效、并且全部严格低于各自阈值，才累计空闲时间。任何一项繁忙、缺失、报错，或睡眠、长采样中断、配置修改，都会重新开始计时。

默认：180 分钟持续低使用率、60 秒采样、60 秒关机预告。所有指标默认选中：CPU/GPU/磁盘 5%，网络 32 KiB/s。首次运行暂停，需主动开始。

- CPU：系统平均忙碌率；多处理器组机器保守拒绝不完整读数
- GPU：将同一硬件引擎的进程贡献相加，再取最忙引擎；仅能覆盖驱动实际公开的计数器
- 磁盘：最忙物理磁盘的活动时间百分比，即每个物理盘 `100 − % Idle Time` 的最大值，排除 `_Total`；不是磁盘吞吐带宽，也不等于队列长度
- 网络：所有已启用、非回环接口的接收+发送总量；包括 VPN/虚拟接口，可能重复计数，从而延后关机
- 默认会话保护：有人保持连接的控制台/RDP 会话会阻止计时；仍连接的锁屏也可能阻止。断开 RDP 后可以计时，重连会重置。可在界面明确关闭这项额外保护

**低资源使用率不能证明没有重要工作。** 等待输入、等待远端、慢速任务、某些 GPU 模式都可能不适合自动关机。采样观察的是区间平均值，不能证明采样间没有短暂活动。GPU/驱动未公开完整信息时不能承诺完整硬件覆盖。

## 两种启动方式

1. 登录启动（推荐）：设置一次，登录 Windows 后运行；断开远程桌面后继续。注销会停止；电脑重启后首次登录前不会监测
2. 开机服务：管理员明确安装后以 LocalService 身份运行，登录前即可监测。设置界面按需打开，关闭界面不会停止服务。系统级互斥门防止与登录监测并行

安装/切换服务需要 Windows 管理员确认。程序安装到固定 Program Files 路径，配置在受保护的 ProgramData 路径；普通用户可查询或取消，修改配置需要管理员。服务没有交互式预告窗口；默认会话保护下，重新连接即可在提交前阻止关机。关闭保护后，不能依赖未打开的设置界面提醒你。

取消会暂停当前监测。登录模式尝试保存暂停状态，保存失败会提示。**服务取消只保持到服务重启/电脑重启；之后按已保存配置重新开始完整计时。** 要跨重启禁用服务监测，用管理员保存禁用配置或移除服务。

## 安全演练

不要先启用真实关机。解压后先运行：

```
QuietGuard.exe --self-test
QuietGuard.exe --dry-run
```

`--self-test` 只运行内置纯逻辑测试，返回 0 为通过；GUI 子系统程序不保证终端可见输出，可通过 PowerShell Start-Process -Wait -PassThru 查看 ExitCode。

`--dry-run` 使用真实传感器和同一状态机/提交路径，但关机调用立即返回，不接触电源 API，也不修改启动项。界面醒目标注“安全演练”。普通 `--dry-run` 与安装/删除/配置动作混用会被拒绝。

服务模式的独立、**会安装服务**的测试入口，仅在管理员明确批准且可恢复的 Windows 测试机执行：

```
QuietGuard.exe --install-service-dry-run --config "C:\approved-test\settings.ini"
```

这个显式安装动作注册 `--service-dry-run`，同一最终提交点不执行关机。必须在安装前确认目标、管理员权限、服务变化及清理步骤。云端开发没有执行过此动作。

真正关机使用不强制关闭应用的 Windows API；应用可能阻止关机。界面显示的是“Windows 已接受请求”，不等于已经关机。取消保障截至程序的提交点，之后不能承诺撤回。

## 不操作界面的真实传感器测试

原来的 `--dry-run` 只打开安全演练界面，未按“开始”时仍然暂停。0.3新增独立的 `--sensor-test`：它实际创建、读取和释放同一套 CPU/GPU/磁盘/网络传感器，但这条控制流没有关机、服务控制、登录启动或生产配置写入调用，也不操作已有实例。

在另行明确授权的 Windows 测试会话中，使用绝对路径，选择一个不存在的新报告文件：

```
C:\QuietGuard\QuietGuard.exe --sensor-test --metrics all --duration-seconds 720 --interval-seconds 60 --sample-timeout-seconds 15 --output C:\QG-results\new-run.json
```

父目录须已存在。默认约12分钟；前两个采样间隔标为预热。也可只选择 `cpu`、`gpu`、`disk`、`network` 或逗号连接的组合。读数不可用会明确记录为未知，不能当作0。输出会记录实际有效样本、CPU累计时间、内存、句柄/线程、进程I/O和退出原因；仅在结束时写一次有界JSON报告。

可选的 `scripts/Measure-Safe-Sensors.ps1` 验证EXE与同目录 `PROVENANCE.json`，运行全指标或五组短测并汇总。用新的 PowerShell 会话，保持已有执行策略；脚本被策略阻止时不绕过。完整说明见 `docs/SAFE-MEASUREMENT.md`。

这测的是独立诊断进程，同一传感器代码加上测量开销；不是GUI/服务最终性能。进程I/O也不等于物理磁盘或驱动/系统提供方总成本。已有生产实例完全不受该入口控制，因此测试前应独立确认真实实例处于安全暂停状态。阻塞的提供方会被标记超时，必要时仅结束测试进程，绝不结束已有实例。

## 资源开销

没有 WebView/.NET GUI、网络遥测、后台动画、轮询子进程、周期日志或周期配置写入。正常监测每个采样间隔唤醒一次，仅选择的传感器工作。短预告期间加快到最多每 2 秒采样。登录界面隐藏后无界面刷新定时器；IPC 和传感器分属睡眠线程，以免慢驱动阻塞取消。

这不代表“零开销”。特别是 GPU/磁盘性能计数器可能把开销放在系统/驱动提供方。CPU、RAM、实际磁盘 I/O 必须在目标 Windows 电脑上测量。见 `docs/VALIDATION.md` 和只读测量脚本 `scripts/Measure-QuietGuard.ps1`。

## 当前验证限制

Linux 逻辑和 mock 检查不能代替真实 Windows 验证。完整测试脚本仍有一个已知缺陷：安全入口 mutation 测试创建临时副本时没有复制所需的 PowerShell 脚本，因文件缺失停止；不能称完整套件通过。此源码快照保留原测试行为。

0.3.1 的 Windows 构建、界面、传感器、服务和真实关机验证尚待完成。原磁盘异常根因未解决。资源清单中的应用版本仍为 0.3.0.0，而产品源码和版本资源为 0.3.1；本次文档与许可整理未修改这些原始版本字段。详见 [验证范围](docs/VALIDATION.md)。
